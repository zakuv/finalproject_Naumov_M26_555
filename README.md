# ValutaTrade Hub

Учебное консольное приложение для симуляции валютного кошелька:
регистрация пользователей, управление портфелем, покупка и продажа валют.
Отдельный Parser Service получает фиатные и криптовалютные курсы
из CoinGecko и ExchangeRate-API для локального кэша и истории измерений.

## Требования

- Python 3.12 или новее.
- uv 0.12.18 или новее.
- Make для сокращённых команд; также можно использовать uv напрямую.

## Установка и запуск

В каталоге проекта:

```bash
make install
make run
```

Без Make:

```bash
uv sync --locked
uv run valutatrade
```

Также доступны `make project`, `uv run project` и `uv run python main.py`.
Версии зависимостей зафиксированы в `uv.lock`. PrettyTable установлен
для вывода таблиц; Ruff находится в группе зависимостей для разработки.

## Регистрация и вход

После `make run` вводите команды в приглашении `Введите команду:`:

```text
register --username alice --password 1234
login --username alice --password 1234
logout
exit
```

- `register` создаёт пользователя и пустой портфель без начального баланса.
  Имя должно быть непустым и уникальным, пароль — не короче четырёх символов.
  Регистрация не выполняет вход автоматически.
- `login` проверяет пароль и устанавливает текущего пользователя.
  Ошибка входа сохраняет прежнюю активную сессию.
- `logout` сбрасывает текущую сессию.
- `help` показывает доступные команды, `help register` — синтаксис регистрации.
- `exit`, EOF (`Ctrl+D`) или `Ctrl+C` завершают приложение.

Для значений с пробелами используйте кавычки:

```text
register --username "Анна Мария" --password "мой пароль"
login --username "Анна Мария" --password "мой пароль"
```

Пробелы по краям имени убираются; пароль сравнивается точно, включая пробелы.
Пароль сохраняется в виде хеша с солью. Сессия хранится в памяти процесса:
после перезапуска нужно войти заново, пользователи и портфели остаются в JSON.
Ошибки команд выводятся без завершения приложения; введённый пароль
не повторяется в сообщениях об ошибках.

## Портфель и валютные операции

Поддерживаются USD, EUR, GBP, RUB, BTC, ETH и SOL. Команды `show-portfolio`, `buy`
и `sell` доступны после входа. `get-rate` можно использовать без входа.

После регистрации `alice` выполните в консоли:

```text
login --username alice --password 1234
show-portfolio
buy --currency BTC --amount 0.05
buy --currency EUR --amount 200
show-portfolio
show-portfolio --base EUR
sell --currency BTC --amount 0.01
get-rate --from USD --to BTC
```

`show-portfolio` выводит кошельки через PrettyTable и итоговую стоимость
в выбранной базовой валюте (по умолчанию USD, меняется в настройках).
Балансы восстанавливаются после перезапуска приложения.

Симуляция следует подробному сценарию команд из раздела 2.2 задания:
`buy --amount` пополняет кошелёк указанным количеством самой валюты,
`sell --amount` списывает это количество. Оценочная стоимость покупки
или выручка продажи показывается в USD. При первой покупке кошелёк
создаётся автоматически. Сумма должна быть положительным конечным числом.
При недостатке средств, неизвестной валюте или ошибке получения курса
операция завершается сообщением об ошибке, сохранённый баланс остаётся прежним.

## Курсы и свежесть кэша

`get-rate --from USD --to BTC` показывает прямой и обратный курс,
время обновления и источник. Поддерживаются прямые пары, обратные пары
и пересчёт через USD; курс валюты к самой себе равен единице.

`RateService` хранит котировки в `data/rates.json` в формате финального
Parser Service:

```json
{
    "pairs": {
        "BTC_USD": {
            "rate": 59337.21,
            "updated_at": "2026-10-15T12:00:00+00:00",
            "source": "CoinGecko"
        }
    },
    "last_refresh": "2026-10-15T12:00:00+00:00"
}
```

Пара `BTC_USD` означает количество USD за один BTC.
Параметр `rates_ttl_seconds` по умолчанию равен 300 секундам.
Свежесть проверяется по
`updated_at` нужной котировки. Для пересчёта через USD обе котировки
должны быть свежими, время результата соответствует более старой из них.
`last_refresh` обозначает время общего обновления кэша. Метки времени
нормализуются в UTC; ISO-даты без часового пояса считаются UTC.

Если свежий курс отсутствует, Core запускает обновление Parser Service
и перечитывает кэш. При сбое источника ранее сохранённые котировки остаются
на месте, но устаревший курс не используется для сделки. Сообщение об ошибке
предлагает выполнить `update-rates`. Успешное обновление других пар
не делает старую котировку свежей. Автоматической подмены курсов
фиксированными значениями нет.

## Parser Service

Для фиатных валют получите ключ на
[ExchangeRate-API](https://www.exchangerate-api.com/) и задайте переменную
окружения **до запуска** приложения:

```bash
export EXCHANGERATE_API_KEY='ваш_ключ'
uv run valutatrade
```

В PowerShell: `$env:EXCHANGERATE_API_KEY = 'ваш_ключ'`.
В PyCharm переменная задаётся в Run/Debug Configuration → Environment variables.
Ключ хранится в окружении, не в исходном коде. `.env.example` показывает имя
переменной; файлы `.env` исключены из Git и автоматически не загружаются.
CoinGecko использует публичный endpoint без ключа, как в задании.

В интерактивной консоли доступны:

```text
update-rates
update-rates --source coingecko
update-rates --source exchangerate
show-rates
show-rates --currency RUB
show-rates --top 2
show-rates --currency BTC --base EUR
```

`update-rates` опрашивает оба источника или выбранный через `--source`.
Если один API недоступен, курсы другого сохраняются, а команда сообщает
о частичной ошибке. При полном отказе кэш и история остаются прежними.
Для запросов задан таймаут 10 секунд. Ошибки HTTP 401, 429, сети и
неверного JSON преобразуются в `ApiRequestError`.

`show-rates` читает только локальный кэш. `--currency` фильтрует исходную
валюту, `--top N` выбирает N самых дорогих криптовалют, `--base` пересчитывает
котировки в выбранную валюту. Таблица показывает время и источник;
устаревшие строки помечаются с предложением обновить данные.

`ParserConfig` в `parser_service/config.py` содержит URL, списки валют,
`CRYPTO_ID_MAP`, базу USD, пути, таймаут и интервал обновления.
Пути берутся из тех же настроек, что использует Core.
Парсер работает отдельно по таймеру:

```bash
uv run python -m valutatrade_hub.parser_service.scheduler
uv run python -m valutatrade_hub.parser_service.scheduler --interval 300 --source coingecko
```

Остановка — `Ctrl+C`. Внешний планировщик также может запускать этот модуль.

Пара `EUR_USD` означает USD за 1 EUR. Ответ ExchangeRate-API с базой USD
содержит количество EUR за USD, поэтому клиент берёт обратное значение.
Поддерживаются поле `conversion_rates` из
[официального v6 API](https://www.exchangerate-api.com/docs/standard-requests)
и поле `rates` из примера задания. Формат запроса CoinGecko —
[simple/price с ids и vs_currencies](https://docs.coingecko.com/reference/simple-price).

`updated_at` в кэше и `timestamp` в истории обозначают время успешного
получения проверенных данных в UTC. TTL оценивает давность получения;
исходное время обновления фиатного API сохраняется в `meta.api_updated_at`.
Новый срез заменяет котировку только при более свежем `updated_at`.
История `data/exchange_rates.json` — список записей с `id` из пары и времени,
`from_currency`, `to_currency`, `rate`, `timestamp`, `source` и `meta`.
Повторное сохранение одного измерения не создаёт дубликат.
Кэш и история записываются атомарно через временный файл и `os.replace`.

## Валюты и ошибки

`Currency` — абстрактный класс с именем, кодом и методом
`get_display_info()`. `FiatCurrency` добавляет страну эмиссии,
`CryptoCurrency` — алгоритм и капитализацию. Фабрика `get_currency(code)`
нормализует код и возвращает объект поддерживаемой валюты:

```python
from valutatrade_hub.core.currencies import get_currency

print(get_currency("usd").get_display_info())
# [FIAT] USD — US Dollar (Issuing: United States)
```

Метаданные криптовалют пока учебные; нулевая капитализация в реестре
обозначает отсутствие загруженных рыночных данных.

- `InsufficientFundsError` сообщает доступный и требуемый баланс.
- `CurrencyNotFoundError` означает неизвестный код; CLI предлагает `help get-rate`.
- `ApiRequestError` сообщает об ошибке получения курса и предлагает повторить запрос.
- `StorageError` и `ConfigurationError` объясняют ошибку файла или настроек.

Исключения обрабатываются в CLI. Ошибка отдельной команды позволяет продолжить
ввод, ошибка подготовки настроек, хранилища или журнала завершает запуск с кодом 1.

## Настройки и журнал операций

Параметры находятся в секции `[tool.valutatrade]` файла `pyproject.toml`
в текущей рабочей папке:

```toml
[tool.valutatrade]
data_dir = "data"
users_file = "users.json"
portfolios_file = "portfolios.json"
rates_file = "rates.json"
history_file = "exchange_rates.json"
rates_ttl_seconds = 300
default_base_currency = "USD"
log_file = "logs/actions.log"
log_level = "INFO"
log_format = "json"
log_max_bytes = 1048576
log_backup_count = 3
```

Пути разрешаются относительно папки конфигурации. При запуске установленного
пакета из папки без `pyproject.toml` используются эти же значения по умолчанию
относительно рабочей папки. Имена JSON-файлов должны различаться и не содержать
путей; каталог задаётся через `data_dir`.

`SettingsLoader()` возвращает единственный экземпляр с закэшированной
конфигурацией; `get(key, default)` читает параметр. `reload()` перечитывает файл,
а `reload(path)` выбирает другой. При ошибке перезагрузки прежние настройки
сохраняются. CLI получает их при запуске; после изменения настроек приложение
следует перезапустить.

Декоратор `@log_action` записывает успешные и неудачные `BUY`/`SELL` в
`logs/actions.log`. Формат — JSON, одна запись на строку: время ISO в UTC,
действие, пользователь, валюта, количество, курс, база и результат `OK`/`ERROR`.
При ошибке добавляются её тип и сообщение, исключение передаётся в CLI.
Опция `verbose=True` добавляет баланс до и после успешной операции.
Пароль, его хеш и соль в записи не включаются.

Журнал использует уровень INFO (можно выбрать DEBUG). При достижении
1 МиБ файл ротируется; сохраняются до трёх резервных файлов `actions.log.1`
и далее. Размер и число копий меняются параметрами `log_max_bytes` и
`log_backup_count`. Повторная настройка журнала не дублирует обработчики.
Parser Service пишет отдельный журнал `logs/parser.log` с той же ротацией.

## Модели

- `User.create()` создаёт пользователя с уникальной солью и хешем SHA-256.
  Пароль должен содержать не меньше четырёх символов, имя — быть непустым.
  `get_user_info()` возвращает информацию без хеша и соли.
- `Wallet` хранит неотрицательный баланс. Пополнение и снятие принимают
  только положительные конечные числа. При недостатке средств возникает
  `InsufficientFundsError`, баланс сохраняется. Валюта кошелька задаётся
  при создании и доступна для чтения.
- `Portfolio` хранит кошельки одного пользователя. Повторное добавление
  валюты возвращает существующий кошелёк. Свойство `wallets` возвращает
  копию словаря, содержащую те же объекты `Wallet`; `user` доступно для чтения.

При самостоятельном использовании моделей доступны учебные курсы из задания:
`EUR_USD = 1.0786`, `BTC_USD = 59337.21`, `RUB_USD = 0.01016`,
`ETH_USD = 3720.00`. Поддерживаются обратные курсы и пересчёт через USD.
При работе через CLI сервис использует котировки Parser Service,
проверяет свежесть кэша и передаёт курсы в модель портфеля. В метод
`get_total_value()` также можно передать собственный числовой словарь
котировок через `exchange_rates`.

Пример работы с моделями:

```python
from valutatrade_hub.core.models import Portfolio, User

user = User.create(1, "alice", "1234")
portfolio = Portfolio(user)
portfolio.add_currency("USD").deposit(1000)
portfolio.add_currency("BTC").deposit(0.01)

print(user.verify_password("1234"))  # True
print(f"Стоимость: {portfolio.get_total_value():.2f} USD")  # 1593.37 USD
```

Конструктор `User` принимает сохранённые `user_id`, `username`,
`hashed_password`, `salt` и `registration_date`. Для нового пользователя
используется `User.create()`. Методы `to_dict()` и `from_dict()` готовят
модели к JSON и восстанавливают их; дата регистрации хранится в ISO-формате.

## JSON-хранилище

`DatabaseManager()` предоставляет общее JSON-хранилище приложения с путями
из настроек и реализован как Singleton через `__new__`. `JsonStorage(data_dir)`
позволяет работать с отдельным каталогом. По умолчанию используется `data/`.
Экземпляры синглтонов создаются при обращении, импорт модулей не создаёт файлов.

При первом запуске автоматически создаются отсутствующие файлы:

- `users.json` — список пользователей с хешами паролей, солью и датами;
- `portfolios.json` — список портфелей, связанных с пользователями по ID;
- `rates.json` — пустой кэш `{"pairs": {}, "last_refresh": null}`;
- `exchange_rates.json` — история котировок, изначально пустой список.

Существующие файлы при инициализации сохраняются. Методы `load_users()`
и `load_portfolios()` возвращают объекты моделей. Для портфелей хранилище
восстанавливает связь с владельцем и проверяет, что он существует.
Повторяющиеся ID, имена пользователей и портфели одного владельца
считаются ошибками данных.

```python
from valutatrade_hub.infra.database import JsonStorage

storage = JsonStorage()
users = storage.load_users()
portfolios = storage.load_portfolios(users)
```

Изменения загруженных объектов сохраняются явно: `save_users(users)`
и `save_portfolios(portfolios)`. Для снимка курсов используются
`load_rates()` и `save_rates(snapshot)`. Каждый файл сначала записывается во
временный файл в том же каталоге и затем заменяется через `os.replace`.
Ошибка записи не обнуляет прежнее содержимое. Сохранение пользователей
также проверяет, что у существующих портфелей останутся владельцы.

Некорректный JSON, неверная структура или ошибка доступа вызывают
`StorageError` с указанием файла. Повреждённые данные не заменяются
пустыми списками.

## Проверка и сборка

```bash
make lint
make test
uv run ruff format --check .
make build
make publish
```

`make test` запускает тесты через стандартный `unittest`. Проверки API
используют подставные HTTP-ответы и не требуют сети или настоящего ключа.
`make format` форматирует код. `make build` создаёт wheel и исходный архив
в `dist/`. `make publish` проверяет метаданные сборок через Twine без
отправки на PyPI. `make package-install` устанавливает зависимости из `uv.lock`,
собирает пакет и устанавливает полученный wheel в окружение `.venv`.

Для проверки запуска установленного пакета:

```bash
make package-install
.venv/bin/valutatrade
```

## Демонстрация

`demo/valutatrade-live.cast` — ручная запись работы приложения с настоящими
API CoinGecko и ExchangeRate-API в формате asciinema v2. Показаны регистрация,
вход, покупка, продажа, портфель, получение курса, `update-rates`, фильтры
`show-rates` и ошибки недостатка средств/неизвестной валюты.

Для просмотра записи:

```bash
asciinema play demo/valutatrade-live.cast
```

Пробел ставит воспроизведение на паузу и продолжает его, Ctrl+C завершает
просмотр. Для просмотра готовой записи сеть и API-ключ не нужны.
